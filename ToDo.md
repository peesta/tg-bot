## База данных

### Схема и миграция

- [ ] Хранить сроки продукции целым количеством дней: переименовать поля в
  `fridge_storage_days` и `freezer_storage_days` и подготовить миграцию
  существующих данных.
- [ ] Привести таблицы `products`, `freezer_stock`, `fridge_batches`,
  `operations`, `users` и `settings` к целевой схеме из спецификации.
- [ ] Включать `PRAGMA foreign_keys = ON` для каждого соединения SQLite.
- [ ] Настроить связь `operations.batch_id` с `ON DELETE SET NULL`, чтобы
  исчерпанные партии можно было удалять без удаления журнала операций.

### Модели и публичный API

- [ ] Добавить модели `Product`, `Stock`, `Batch`, `Operation`, `User` и
  `NotificationSettings`.
- [ ] Не возвращать из `Database` сырые `sqlite3.Row`, готовые Telegram-тексты
  или `False`; возвращать модели либо явные прикладные ошибки.
- [ ] Реализовать создание, получение, список, изменение и удаление товаров.
- [ ] Запрещать удаление товара, пока он присутствует в морозильнике или
  холодильнике.
- [ ] Добавить `get_freezer_stock()`, переименовать
  `freezer_products_list()` в `list_freezer_stock()` и сортировать список по
  названию товара.
- [ ] Переименовать `move_to_fridge()` в `create_defrost_batch()` и возвращать
  модель `Batch`.
- [ ] Добавить `get_batch()`, переименовать `fridge_batches_list()` в
  `list_fridge_batches()` и возвращать модели `Batch`.
- [ ] Переименовать `get_expiring_products()` в `get_expiring_batches()` и
  всегда возвращать список моделей одного типа.
- [ ] Выделить продажу и списание из `clear_expired_product()` в отдельные
  публичные методы `sell_batch()` и `write_off_batch()`.
- [ ] Реализовать `list_operations()` с фильтрами по типу операции и периоду.

### Валидация и расчёт сроков

- [ ] Проверять наличие товара в справочнике в `new_delivery()` до изменения
  морозильного остатка.
- [ ] Нормализовать названия товаров и обеспечить уникальность без учёта
  регистра.
- [ ] Позволить передавать дату и время в методы выборки и разморозки, чтобы
  расчёты можно было стабильно тестировать.

### Пользователи

- [ ] Реализовать ручное добавление пользователя администратором по Telegram ID,
  отображаемому имени и роли.
- [ ] Реализовать получение и список пользователей, изменение роли и
  включение/отключение доступа.
- [ ] Не создавать пользователей автоматически при `/start`; допускать только
  заранее добавленные активные учётные записи.
- [ ] Реализовать получение и изменение времени ежедневных уведомлений и
  часового пояса через таблицу `settings`.
- [ ] Проверять административные права в сервисном слое для управления
  товарами, пользователями и настройками.

### Проверка

- [ ] Добавить тест миграции существующей БД на новую схему.
- [ ] Покрыть тестами отказ при недостаточном остатке и проверить отсутствие
  частичных изменений.
- [ ] Покрыть тестами нулевое, отрицательное и нецелочисленное количество.
- [ ] Покрыть тестами расчёт срока в днях, несколько отдельных партий одного
  товара и выборку истекающих партий.
- [ ] Покрыть тестами полную продажу с удалением партии и списание с
  пользовательской причиной.
- [ ] Покрыть тестами внешние ключи, права ролей и rollback при исключении.
