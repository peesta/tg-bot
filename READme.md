# Техническое задание

Документация готовой части базы данных:
[`storage/README.md`](storage/README.md).

## Назначение

Разработать Telegram-бота для учёта сроков годности продукции на предприятии общественного питания (кафе, суши-бар, пекарня и т.д.).

Бот должен помогать сотрудникам:

- учитывать продукцию, доставаемую из заморозки;
- контролировать сроки годности;
- выводить список продукции с истекающим сроком;
- оформлять списание просроченной продукции;
- минимизировать ручной ввод данных за счёт кнопок.

---

## Основные требования

### Требования к БД

[x] 1. Справочник продукции

Должен существовать список продукции.

Для каждого товара задаются:

- название;
- срок хранения после разморозки (целое количество дней);
- категория (по желанию).

Пример:

Товар| Срок хранения
Филадельфия| 2 дня
Калифорния| 2 дня
Лосось| 3 дня



Администратор должен иметь возможность добавлять новые позиции и изменять сроки хранения.

---

2. Главное меню

После запуска бот показывает кнопки:

📦 Достать из заморозки

⚠ Сегодня заканчивается срок

🗑 Списание

📊 Остатки

⚙ Управление товарами (только администратор)

---

3. Достать из заморозки - Реализовано в базе данных

При нажатии кнопки:

"📦 Достать из заморозки"

бот предлагает выбрать товар из списка.

После выбора товара бот предлагает выбрать количество.

Количество можно:

- выбрать кнопками;
- либо ввести вручную.

После подтверждения бот:

1. создаёт новую партию;
2. автоматически рассчитывает дату и время окончания срока годности;
3. уменьшает остаток в морозильнике;
4. сохраняет данные в базе.

Если после разморозки остаток товара в морозильнике стал равен нулю, запись
этого товара удаляется из морозильника.

Пример ответа:

Добавлено:

Филадельфия — 5 шт

Дата разморозки:
17.08.2026 09:00

Годен до:
19.08.2026 09:00

---

4. Учёт партий - реализовано

Каждая разморозка должна храниться отдельно.

Пример:

Филадельфия — 5 шт — годна до 19.08

Филадельфия — 3 шт — годна до 20.08

Бот не должен объединять партии с разными сроками.

---

5. Остатки - реализовано в БД

Кнопка:

📊 Остатки

Показывает все существующие партии с положительным остатком.

Пример:

Филадельфия — 5 шт — до 19.08

Калифорния — 3 шт — до 20.08

Лосось — 4 шт — до 21.08

Просроченные партии отображать отдельно.

---

7. Списание продукции - реализовано в базе данных

Кнопка:

🗑 Списание

Появляется список партий из 5 штук на странице, это кнопки. Под ними еще 3 кнопки "<Назад" "Поиск" "Далее>".

Пример:

*Выберите продукт* стр. 2 из 5

[Медовик - 3 до 2026-08-03]
[Мотти - 2 до 2026-08-03]
[Сэндвич - 1 до 2026-08-04]
[Чизкейк - 3 до 2026-08-04]
[Медовик - 2 до 2026-08-05]

[ < Назад ] [ Поиск ] [ Далее > ]

После выбора сообщение меняется на:

*Выбран:*
Медовик - 3 до 2026-08-03

[ Списать ]
[ Продано ]

При выборе "Списать", вылезает новое сообщение:

*Причина списания?*

[ Просрочено ]
[ Повреждено ]
[ Для сотрудника ]
[ Другая причина ]

При выборе другой причины бот просит написать причину вручную.

После выбора причины, он спросит количество, которое нужно списать, вводится число с клавиатуры.

---
При выборе "Продано", бот просит ввести количество проданного товара.

---

8. История списаний - реализовано в базе данных с запасом(логируются все операции)

Бот должен хранить:

- дату;
- товар;
- количество;
- причину списания.

Кнопка:

📋 История списаний

Показывает журнал списаний.

---

9. Роли пользователей - реализовано в БД

Необходимо минимум две роли.

Администратор

Может:

- добавлять товары;
- удалять товары;
- менять сроки хранения;
- вручную добавлять сотрудников;
- назначать сотрудникам роли и отключать им доступ.

Для добавления сотрудника администратор указывает его Telegram ID и отображаемое
имя. Автоматическая регистрация пользователей при запуске бота или выполнении
команды `/start` не выполняется.

Сотрудник

Может:

- добавлять разморозку;
- просматривать остатки;
- выполнять списание.

---

# Отложенная функциональность

На текущем этапе не планируются:

- самостоятельная или автоматическая регистрация пользователей — сотрудников
  вручную добавляет администратор;
- раздел «📈 Статистика», включая расчёт количества размороженной, проданной и
  списанной продукции, процента списаний и выбор периода.

История операций и списаний продолжает сохраняться независимо от отсутствия
раздела статистики.

## Уведомление в начале смены

Каждый день в установленное время (например 09:00) бот автоматически отправляет сообщение.

Пример:

⚠ Сегодня заканчивается срок годности:

Филадельфия — 2 шт

Калифорния — 4 шт

Необходимо реализовать настройку времени уведомления.
