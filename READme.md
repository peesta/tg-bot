# Техническое задание

План реализации Telegram-части: [`ToDo.md`](ToDo.md).

## Запуск

1. Установить зависимости: `pip install -r requirements.txt`.
2. Создать файл `.env` по образцу [`.env.example`](.env.example):
   - `TELEGRAM_KEY` — токен бота от @BotFather;
   - `ADMIN_IDS` — Telegram ID администраторов через запятую. У них всегда
     есть доступ к боту, даже если их нет в таблице пользователей: так
     появляется первый администратор, который добавляет остальных;
   - `GOOGLE_TABLE` — ссылка на Google Таблицу для экспорта и импорта
     (см. ниже).
3. Запустить: `python main.py`.

База данных создаётся в `data/database.db`. Время в боте — время сервера.

Свой Telegram ID можно узнать, написав боту любое сообщение: пользователю
без доступа бот отвечает отказом и показывает его ID.

## Google Таблица

В «⚙ Настройки» у администратора есть кнопки «📤 Экспорт в Google Таблицу»
и «📥 Импорт из Google Таблицы». Таблица одна, в ней три листа с названиями
как у таблиц базы: `products`, `freezer`, `fridge`. В первой строке листа —
названия столбцов, как в базе:

| Лист       | Столбцы                                                         |
| ---------- | --------------------------------------------------------------- |
| `products` | `name`, `fridge_storage_time`, `freezer_storage_time`, `category` |
| `freezer`  | `product_name`, `quantity`                                      |
| `fridge`   | `id`, `product_name`, `quantity`, `date_added`, `expiration_date` |

Экспорт стирает эти три листа и записывает в них текущие данные из базы.
Остальные листы таблицы не трогаются, недостающие листы создаются.

Импорт заменяет товары, морозильник и холодильник в базе данными из листов.
Сотрудники и журнал операций не меняются, импорт в журнал не пишется.
Перед заменой бот проверяет все строки и при любой ошибке ничего не меняет,
а показывает список ошибок с номерами строк. Перед заменой копия базы
сохраняется в `data/backups/`.

Правила для импорта:
- `fridge_storage_time`, `quantity` — целые числа больше нуля;
  `freezer_storage_time` и `category` можно не заполнять;
- товар на листе `freezer` должен быть на листе `products`;
- даты — `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ`; пустой `date_added` — сегодня;
- пустой `id` партии — бот присвоит новый номер.

Настройка доступа:
1. В Google Cloud включить Google Sheets API и Google Drive API, создать
   сервисный аккаунт и JSON-ключ к нему.
2. Положить ключ в корень проекта под именем `credentials.json` (файл в
   `.gitignore`, в git не попадает).
3. В таблице открыть «Настройки доступа» и добавить почту сервисного
   аккаунта (`client_email` из ключа) с правами «Редактор».
4. Записать ссылку на таблицу в `GOOGLE_TABLE` в `.env`.

## Назначение

Разработать Telegram-бота для учёта сроков годности продукции на предприятии общественного питания (кафе, суши-бар, пекарня и т.д.).

Бот должен помогать сотрудникам:

- учитывать продукцию, доставаемую из заморозки;
- контролировать сроки годности;
- выводить список продукции с истекающим сроком;
- оформлять списание просроченной продукции;
- оформлять продажи продуктов;
- минимизировать ручной ввод данных за счёт кнопок.

## Основные требования

### Требования к БД

[x] 1. Справочник продукции

Должен существовать список продукции.

Для каждого товара задаются:

- название;
- срок хранения после разморозки (целое количество дней);
- срок хранения в морозильнике (пока что это поле пустое);

Пример:

Товар| Срок в холодильнике
Филадельфия| 2 дня
Калифорния| 2 дня
Лосось| 3 дня

Администратор должен иметь возможность добавлять новые позиции и изменять сроки хранения.

2. Главное меню

После запуска бот показывает кнопки:

📦 Достать из заморозки

❄️ Добавить заморозку

⚠ Сегодня заканчивается срок

🗑 Списание и продажа

📊 Остатки

📋 История списаний

⚙ Настройки: товары и сотрудники (только администратор)

---

2.1. Добавить заморозку

Кнопка:

❄️ Добавить заморозку

Бот предлагает выбрать товар из справочника товаров (все позиции, которые
продаются), по 5 на странице, с кнопками «Назад», «Поиск», «Далее».

Затем бот предлагает выбрать количество: 1, 2, 3 или «Ввести число».

После выбора количества товар добавляется в морозильник (если он там уже
есть, остаток увеличивается), операция записывается в журнал.

---

3. Достать из заморозки - Реализовано в базе данных

При нажатии кнопки:

"📦 Достать из заморозки"

бот предлагает выбрать товар из списка.

После выбора товара бот предлагает выбрать количество.

Количество можно:

- выбрать кнопками;
- либо ввести вручную.

После подтверждения бот:

1. создаёт новую партию;
2. автоматически рассчитывает дату и время окончания срока годности;
3. уменьшает остаток в морозильнике;
4. сохраняет данные в базе.

Если после разморозки остаток товара в морозильнике стал равен нулю, запись
этого товара удаляется из морозильника.

Пример ответа:

Добавлено:

Филадельфия — 5 шт

Дата разморозки:
17.08.2026 09:00

Годен до:
19.08.2026 09:00

---

4. Учёт партий - реализовано

Каждая разморозка должна храниться отдельно.

Пример:

Филадельфия — 5 шт — годна до 19.08

Филадельфия — 3 шт — годна до 20.08

Бот не должен объединять партии с разными сроками.

---

5. Остатки - реализовано в БД

Кнопка:

📊 Остатки

Показывает все существующие партии с положительным остатком.

Пример:

Филадельфия — 5 шт — до 19.08

Калифорния — 3 шт — до 20.08

Лосось — 4 шт — до 21.08

Просроченные партии отображать отдельно.

7. Списание продукции - реализовано в базе данных

Кнопка:

Кнопка:

---

9. Роли пользователей - реализовано в БД

Необходимо минимум две роли.

Администратор

Может:

- добавлять товары;
- удалять товары;
- менять сроки хранения;
- вручную добавлять сотрудников;
- назначать сотрудникам роли и отключать им доступ.

Для добавления сотрудника администратор указывает его Telegram ID и отображаемое
имя. Автоматическая регистрация пользователей при запуске бота или выполнении
команды `/start` не выполняется.

Сотрудник

Может:

- добавлять разморозку;
- просматривать остатки;
- выполнять списание.

# Отложенная функциональность

На текущем этапе не планируются:

- самостоятельная или автоматическая регистрация пользователей — сотрудников
  вручную добавляет администратор;
- раздел «📈 Статистика», включая расчёт количества размороженной, проданной и
  списанной продукции, процента списаний и выбор периода.

История операций и списаний продолжает сохраняться независимо от отсутствия
раздела статистики.

## Уведомление в начале смены

Расписание смен к боту не подключено, поэтому уведомление не рассылается
всем в фиксированное время. Его получает каждый пользователь после своего
первого за день действия в боте (команды или нажатия кнопки) — не больше
одного раза в день.

Уведомление не отправляется, если продуктов с истекающим сроком нет, а также
если пользователь первым делом сам открыл «⚠ Сегодня заканчивается срок».

Пример:

⚠ Сегодня заканчивается срок годности:

Филадельфия — 2 шт

Калифорния — 4 шт

Просроченные партии, которые ещё не списаны, перечисляются отдельно.
