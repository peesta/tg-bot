# Учёт сроков годности — сайт для планшета

Сайт для учёта продукции на предприятии общественного питания: заморозка,
разморозка партий, сроки годности, списание и продажи. Раньше это был
Telegram-бот (он остался в ветке `main`). Стек: Vue 3 (папка `frontend/`) и
FastAPI (папка `api/`), база — SQLite через `storage/db.py`.
План работ: [`ToDo.md`](ToDo.md).

## Запуск

Нужны Python 3.11+ и Node.js 22.12+ (Node — только для сборки фронтенда).

1. `pip install -r requirements.txt`
2. Собрать фронтенд: `cd frontend && npm install && npm run build`.
   Сборка только готовит файлы в `frontend/dist` и завершается — ссылку на
   сайт она не выдаёт. Пересобирать нужно после каждого изменения фронтенда.
3. По желанию создать `.env` по образцу [`.env.example`](.env.example):
   - `HOST`, `PORT` — адрес и порт (по умолчанию `127.0.0.1:8000`). Чтобы
     сайт открывался с планшетов в сети кафе, укажите `HOST=0.0.0.0`;
   - `SECRET_KEY` — ключ подписи сессий; если не задан, создаётся сам в
     `data/secret_key`;
   - `SECURE_COOKIES=1` — если сайт работает только по HTTPS;
   - `GOOGLE_TABLE` — ссылка на Google Таблицу для экспорта и импорта.
4. Из корня проекта: `python main.py`. В консоли появятся ссылки — обычно
   `http://127.0.0.1:8000`, а при `HOST=0.0.0.0` ещё и адрес для планшета
   вида `http://192.168.1.5:8000`. Сайт работает, пока открыто это окно
   консоли; остановить — Ctrl+C.

Если планшет не открывает сайт: компьютер и планшет должны быть в одной
сети, в `.env` — `HOST=0.0.0.0`, а брандмауэр Windows — разрешать входящие
подключения к Python (Windows спросит об этом при первом запуске).

Для разработки фронтенда: `python main.py` в одном окне и
`cd frontend && npm run dev` в другом. Vite выдаст свою ссылку
(`http://localhost:5173`), страницы будут обновляться сразу после правок,
а запросы `/api` уйдут на FastAPI.

База данных — `data/database.db`, журнал сервера — `data/logs/app.log`,
резервные копии — `data/backups/`. Время — время сервера. Даты хранятся как
`ГГГГ-ММ-ДД`, в формат `ДД.ММ.ГГГГ` их переводит только браузер.

База, оставшаяся от Telegram-бота, подходит без переделки: таблицы бота не
меняются. Сотрудники бота видны в разделе «Сотрудники» без логина — войти
они смогут, когда администратор задаст им логин и пароль.

## Учётные записи

Регистрации нет. При первом запуске создаются две учётные записи (пароли
пока простые — для проверки):

| Логин      | Пароль     | Роль          |
| ---------- | ---------- | ------------- |
| `admin`    | `admin`    | администратор |
| `employee` | `employee` | сотрудник     |

Остальных сотрудников добавляет администратор в разделе «Сотрудники».
Если единственный администратор забыл пароль: `python main.py set-password admin`
— задаёт новый пароль и включает доступ (если логина нет, создаёт
администратора).

Администратор не может лишить прав сам себя: сменить себе роль, отключить
себе доступ или удалить себя — ни в «Сотрудниках», ни в редакторе базы.

## Интерфейс

Сайт рассчитан на планшет (альбомная и книжная ориентация): кнопки и поля не
ниже 56 px, крупные быстрые кнопки количества, календарь вместо ввода дат.
Шрифт Roboto Mono трёх размеров — 18, 22 и 28 px, иконки — плоские SVG.

Вкладка браузера всегда называется «Учет товара», её значок — молекула воды
(жёлтый кислород, белый водород): `frontend/public/favicon.svg`. PNG-значки
для главного экрана планшета в той же папке нарисованы по этому SVG — при
смене рисунка их нужно перерисовать.

Сотрудник видит узкое меню слева с крупными значками и плитки на главной.
Администратор — тёмную панель с разделами «Работа» и «Администрирование»
(в книжной ориентации она выезжает по кнопке меню) и сводку на главной.

## Журналы

Всё пишется в базу (`storage/db.py`) и показывается в разделе «Логи»:

- **операции** (`operations`) — заморозка (поставка), разморозка, продажа,
  списание: что, сколько, кто и когда;
- **изменения** (`change_log`) — добавление сотрудников, смена роли и
  доступа, логина и пароля, добавление, изменение и удаление товаров,
  каждая правка ячейки в редакторе базы (было → стало), импорт и экспорт
  Google Таблицы, резервные копии. Журнал изменений с сайта не правится и
  не откатывается при восстановлении из копии;
- **ошибки** (`errors`, с датой) — сбои сайта, отказы базы (например,
  «недостаточно в морозильнике»), неверно заполненные запросы, попытки
  сотрудника открыть раздел администратора, ошибки импорта;
- **журнал сервера** — файл `data/logs/app.log`: запуск, входы и
  неудачные попытки входа.

## Google Таблица

В разделе «Google Таблица» у администратора есть кнопки экспорта и импорта.
Таблица одна, в ней три листа с названиями как у таблиц базы: `products`,
`freezer`, `fridge`. В первой строке листа — названия столбцов, как в базе:

| Лист       | Столбцы                                                         |
| ---------- | --------------------------------------------------------------- |
| `products` | `name`, `fridge_storage_time`, `freezer_storage_time`, `category` |
| `freezer`  | `product_name`, `quantity`                                      |
| `fridge`   | `id`, `product_name`, `quantity`, `date_added`, `expiration_date` |

Экспорт стирает эти три листа и записывает в них текущие данные из базы.
Остальные листы таблицы не трогаются, недостающие листы создаются.

Импорт заменяет товары, морозильник и холодильник в базе данными из листов.
Сотрудники и журнал операций не меняются. Перед заменой сайт проверяет все
строки и при любой ошибке ничего не меняет, а показывает список ошибок с
номерами строк. Перед заменой копия базы сохраняется в `data/backups/`.

Правила для импорта:
- `fridge_storage_time`, `quantity` — целые числа больше нуля;
  `freezer_storage_time` и `category` можно не заполнять;
- товар на листе `freezer` должен быть на листе `products`;
- даты — `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ`; пустой `date_added` — сегодня;
- пустой `id` партии — сайт присвоит новый номер.

Настройка доступа:
1. В Google Cloud включить Google Sheets API и Google Drive API, создать
   сервисный аккаунт и JSON-ключ к нему.
2. Положить ключ в корень проекта под именем `credentials.json` (файл в
   `.gitignore`, в git не попадает).
3. В таблице открыть «Настройки доступа» и добавить почту сервисного
   аккаунта с правами «Редактор» — сайт показывает эту почту в разделе
   «Google Таблица».
4. Записать ссылку на таблицу в `GOOGLE_TABLE` в `.env`.

# Техническое задание

Исходное ТЗ было написано для Telegram-бота. На сайте те же разделы: кнопки
главного меню стали пунктами меню («⚠ Сегодня заканчивается срок» теперь
называется «Скоро испортится» и стоит сразу под «Главной»), «⚙ Настройки» —
разделами администратора, Telegram ID — логином и паролем.

## Назначение

Разработать Telegram-бота для учёта сроков годности продукции на предприятии общественного питания (кафе, суши-бар, пекарня и т.д.).

Бот должен помогать сотрудникам:

- учитывать продукцию, доставаемую из заморозки;
- контролировать сроки годности;
- выводить список продукции с истекающим сроком;
- оформлять списание просроченной продукции;
- оформлять продажи продуктов;
- минимизировать ручной ввод данных за счёт кнопок.

## Основные требования

### Требования к БД

[x] 1. Справочник продукции

Должен существовать список продукции.

Для каждого товара задаются:

- название;
- срок хранения после разморозки (целое количество дней);
- срок хранения в морозильнике (пока что это поле пустое);

Пример:

Товар| Срок в холодильнике
Филадельфия| 2 дня
Калифорния| 2 дня
Лосось| 3 дня

Администратор должен иметь возможность добавлять новые позиции и изменять сроки хранения.

После запуска бот показывает кнопки:

📦 Достать из заморозки

❄️ Добавить заморозку

⚠ Сегодня заканчивается срок

🗑 Списание и продажа

📊 Остатки

📋 История списаний

⚙ Настройки: товары и сотрудники (только администратор)

---

2.1. Добавить заморозку

Кнопка:

❄️ Добавить заморозку

Бот предлагает выбрать товар из справочника товаров (все позиции, которые
продаются), по 5 на странице, с кнопками «Назад», «Поиск», «Далее».

Затем бот предлагает выбрать количество: 1, 2, 3 или «Ввести число».

После выбора количества товар добавляется в морозильник (если он там уже
есть, остаток увеличивается), операция записывается в журнал.

---

3. Достать из заморозки - Реализовано в базе данных

При нажатии кнопки:

"📦 Достать из заморозки"

бот предлагает выбрать товар из списка.

После выбора товара бот предлагает выбрать количество.

Количество можно:

- выбрать кнопками;
- либо ввести вручную.

После подтверждения бот:

1. создаёт новую партию;
2. автоматически рассчитывает дату и время окончания срока годности;
3. уменьшает остаток в морозильнике;
4. сохраняет данные в базе.

Если после разморозки остаток товара в морозильнике стал равен нулю, запись
этого товара удаляется из морозильника.

Пример ответа:

Добавлено:

Филадельфия — 5 шт

Дата разморозки:
17.08.2026 09:00

Годен до:
19.08.2026 09:00

---

4. Учёт партий - реализовано

Каждая разморозка должна храниться отдельно.

Пример:

Филадельфия — 5 шт — годна до 19.08

Филадельфия — 3 шт — годна до 20.08

Бот не должен объединять партии с разными сроками.

---

5. Остатки - реализовано в БД

Кнопка:

📊 Остатки

Показывает все существующие партии с положительным остатком.

Пример:

Филадельфия — 5 шт — до 19.08

Калифорния — 3 шт — до 20.08

Лосось — 4 шт — до 21.08

Просроченные партии отображать отдельно.

- дату;
- товар;
- количество;

Кнопка:

Показывает журнал списаний.

9. Роли пользователей - реализовано в БД

Необходимо минимум две роли.

Администратор

Может:

- добавлять товары;
- удалять товары;
- менять сроки хранения;
- вручную добавлять сотрудников;

Сотрудник

Может:

- добавлять разморозку;
- просматривать остатки;
- выполнять списание.

# Отложенная функциональность

На текущем этапе не планируются:

- самостоятельная или автоматическая регистрация пользователей — сотрудников
  вручную добавляет администратор;
- раздел «📈 Статистика», включая расчёт количества размороженной, проданной и
  списанной продукции, процента списаний и выбор периода.

История операций и списаний продолжает сохраняться независимо от отсутствия
раздела статистики.

## Уведомление в начале смены

Расписание смен не подключено, поэтому уведомление не рассылается всем в
фиксированное время. Каждый пользователь видит его окном после своего первого
за день открытия сайта — не больше одного раза в день.

Уведомление не показывается, если продуктов с истекающим сроком нет, а также
если пользователь первым делом сам открыл «Скоро испортится».

Пример:

⚠ Сегодня заканчивается срок годности:

Филадельфия — 2 шт

Калифорния — 4 шт

Просроченные партии, которые ещё не списаны, перечисляются отдельно.
