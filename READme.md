# Учёт сроков годности — сайт для планшета и телефона

Сайт для учёта продукции на предприятии общественного питания: заморозка,
разморозка партий, сроки годности, списание и продажи. Раньше это был
Telegram-бот (он остался в ветке `main`). Стек: Vue 3 (папка `frontend/`) и
FastAPI (папка `api/`), база — SQLite через `storage/db.py`.
План работ: [`ToDo.md`](ToDo.md).

## Запуск

Нужны Python 3.11+ и Node.js 22.12+ (Node — только для сборки фронтенда).

Запустить `start_win.bat` на wibdows или `start.bash` через git bash/линукс

Либо вручную

1. `pip install -r requirements.txt`
2. Собрать фронтенд: `cd frontend && npm install && npm run build`.
   Сборка только готовит файлы в `frontend/dist` и завершается — ссылку на
   сайт она не выдаёт. Пересобирать нужно после каждого изменения фронтенда.
3. По желанию создать `.env` по образцу [`.env.example`](.env.example):
   - `HOST`, `PORT` — адрес и порт (по умолчанию `127.0.0.1:8000`). Чтобы
     сайт открывался с планшетов в сети кафе, укажите `HOST=0.0.0.0`;
   - `SECRET_KEY` — ключ подписи сессий; если не задан, создаётся сам в
     `data/secret_key`;
   - `SECURE_COOKIES=1` — если сайт работает только по HTTPS;
   - `GOOGLE_TABLE` — ссылка на Google Таблицу для экспорта и импорта.
4. Из корня проекта: `python main.py`. В консоли появятся ссылки — обычно
   `http://127.0.0.1:8000`, а при `HOST=0.0.0.0` ещё и адрес для устройств в локальной сети
   вида `http://192.168.1.5:8000`. Сайт работает, пока открыто это окно
   консоли; остановить — Ctrl+C.

Если планшет не открывает сайт: компьютер и планшет должны быть в одной
сети, в `.env` — `HOST=0.0.0.0`, а брандмауэр Windows — разрешать входящие
подключения к Python (Windows спросит об этом при первом запуске).

Для разработки фронтенда: `python main.py` в одном окне и
`cd frontend && npm run dev` в другом. Vite выдаст свою ссылку
(`http://localhost:5173`), страницы будут обновляться сразу после правок,
а запросы `/api` уйдут на FastAPI.

База данных — `data/database.db`, журнал сервера — `data/logs/app.log`,
резервные копии — `data/backups/`. Время — время сервера. Даты хранятся как
`ГГГГ-ММ-ДД`, в формат `ДД.ММ.ГГГГ` их переводит только браузер.

База, оставшаяся от Telegram-бота, подходит без переделки: таблицы бота не
меняются. Сотрудники бота видны в разделе «Сотрудники» без логина — войти
они смогут, когда администратор задаст им логин и пароль.

## Учётные записи

Регистрации нет. При первом запуске создаются две учётные записи (пароли
пока простые — для проверки):

| Логин      | Пароль     | Роль          |
| ---------- | ---------- | ------------- |
| `admin`    | `admin`    | администратор |
| `employee` | `employee` | сотрудник     |

Остальных сотрудников добавляет администратор в разделе «Сотрудники».
Если единственный администратор забыл пароль: `python main.py set-password admin`
— задаёт новый пароль и включает доступ (если логина нет, создаёт
администратора).

Администратор не может лишить прав сам себя: сменить себе роль, отключить
себе доступ или удалить себя — ни в «Сотрудниках», ни в редакторе базы.

## Интерфейс

Сайт рассчитан на планшет (альбомная и книжная ориентация): кнопки и поля не
ниже 56 px, крупные быстрые кнопки количества, календарь вместо ввода дат.
Шрифт Roboto Mono трёх размеров — 18, 22 и 28 px, иконки — плоские SVG.

На телефоне (экран уже 640 px) те же разделы для сотрудника и администратора:
меню выезжает слева по кнопке ☰ (так же на телефоне, повёрнутом набок),
в верхней строке остаются значки профиля и выхода, таблицы превращаются в
карточки «столбец — значение», окна выезжают снизу во всю ширину, шрифт —
16, 19 и 23 px. Стили телефона — в конце `frontend/src/styles/base.css`.

Вкладка браузера всегда называется «Учет товара», её значок — молекула воды
(жёлтый кислород, белый водород): `frontend/public/favicon.svg`. PNG-значки
для главного экрана планшета в той же папке нарисованы по этому SVG — при
смене рисунка их нужно перерисовать.

Сотрудник видит узкое меню слева с крупными значками и плитки на главной.
Администратор — тёмную панель с разделами «Работа» и «Администрирование»
(в книжной ориентации она выезжает по кнопке меню) и сводку на главной.

| Раздел                                | Сотрудник | Администратор |
| ------------------------------------- | :-------: | :-----------: |
| Главная                               | ✓ | ✓ |
| Скоро испортится (срок истекает сегодня или уже истёк) | ✓ | ✓ |
| Разморозить (достать из морозильника) | ✓ | ✓ |
| Поставка товара: в морозильник (по умолчанию) или сразу в холодильник | ✓ | ✓ |
| Списание                              | ✓ | ✓ |
| Продажа                               | ✓ | ✓ |
| Холодильник: партии в холодильнике и запас в морозильнике | ✓ | ✓ |
| История операций: все операции, продажи или списания | ✓ | ✓ |
| Профиль, смена своего пароля          | ✓ | ✓ |
| Товары: добавить, изменить сроки и категорию, переименовать, удалить | — | ✓ |
| Сотрудники: добавить, роль, доступ, логин и пароль | — | ✓ |
| База данных: таблицы как в Excel, русские названия столбцов | — | ✓ |
| Логи: операции, изменения, ошибки, журнал сервера | — | ✓ |

| Резервные копии: создать, скачать, восстановить | — | ✓ |

## Журналы

Всё пишется в базу (`storage/db.py`) и показывается в разделе «Логи»:

- **операции** (`operations`) — поставка, разморозка, продажа, списание:
  что, сколько, кто и когда. Поставка сразу в холодильник — это `delivery`
  с номером партии (`batch_id`), у поставки в морозильник номера партии
  нет; таблица `operations` при этом не меняется. Разморозки и поставки
  одного товара за день попадают в одну партию холодильника, поэтому у
  нескольких записей журнала может быть один номер партии;
- **изменения** (`change_log`) — добавление сотрудников, смена роли и
  доступа, логина и пароля, добавление, изменение и удаление товаров,
  каждая правка ячейки в редакторе базы (было → стало), импорт и экспорт
  Google Таблицы, резервные копии. Журнал изменений с сайта не правится и
  не откатывается при восстановлении из копии;
- **ошибки** (`errors`, с датой) — сбои сайта, отказы базы (например,
  «недостаточно в морозильнике»), неверно заполненные запросы, попытки
  сотрудника открыть раздел администратора, ошибки импорта;
- **журнал сервера** — файл `data/logs/app.log`: запуск, входы и
  неудачные попытки входа.

python -m unittest -v          # Python: база, API, Google Таблица, настройки

Тесты не обращаются к Google: Google Таблица имитируется в памяти (с ней

## Google Таблица

В разделе «Google Таблица» у администратора есть кнопки экспорта и импорта.
Таблица одна, в ней три листа на русском. В первой строке листа — названия
столбцов на русском (как в разделе «База данных»), даты — `ДД.ММ.ГГГГ`.
База данных при этом не меняется: в ней по-прежнему таблицы `products`,
`freezer`, `fridge` с английскими названиями столбцов.

| Лист          | Таблица базы | Столбцы                                                                    |
| ------------- | ------------ | -------------------------------------------------------------------------- |
| «Товары»      | `products`   | Название, Срок после разморозки, дней, Срок в морозильнике, дней, Категория |
| «Морозильник» | `freezer`    | Товар, Количество, шт.                                                     |
| «Холодильник» | `fridge`     | № партии, Товар, Количество, шт., Добавлено, Годен до                      |

Экспорт стирает эти три листа и записывает в них текущие данные из базы.
Остальные листы таблицы не трогаются, недостающие листы создаются. Листы,
выгруженные раньше под английскими названиями (`products`, `freezer`,
`fridge`), экспорт переименовывает по-русски.

Импорт заменяет товары, морозильник и холодильник в базе данными из листов.
Сотрудники и журнал операций не меняются. Перед заменой сайт проверяет все
строки и при любой ошибке ничего не меняет, а показывает список ошибок с
названиями листов, столбцов и номерами строк. Перед заменой копия базы
сохраняется в `data/backups/`.

Правила для импорта:
- порядок столбцов любой, регистр букв не важен, лишние столбцы
  пропускаются; можно писать коротко — «Количество» вместо «Количество, шт.»;
  старые английские листы и заголовки (`products`, `quantity` и т. д.)
  тоже понимаются;
- «Срок после разморозки, дней» и «Количество, шт.» — целые числа больше
  нуля; «Срок в морозильнике, дней» и «Категорию» можно не заполнять;
- товар на листе «Морозильник» должен быть на листе «Товары»;
- даты — `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД`; пустое «Добавлено» — сегодня;
- пустой «№ партии» — сайт присвоит новый номер.

Как это устроено: `storage/google_sheets.py` читает три таблицы из SQLite
(`Database.stock_tables`) и записывает их на листы через библиотеку
[`gspread`](https://docs.gspread.org/) — она работает с Google Sheets API от
имени сервисного аккаунта. Названия листов и столбцов задаются там же —
`SHEET_TITLES` и `SHEET_COLUMNS`. Файлов Excel (`.xlsx`) сайт не создаёт.

Настройка доступа:
1. В Google Cloud включить Google Sheets API и Google Drive API, создать
   сервисный аккаунт и JSON-ключ к нему.
2. Положить ключ в корень проекта под именем `credentials.json` (файл в
   `.gitignore`, в git не попадает).
3. В таблице открыть «Настройки доступа» и добавить почту сервисного
   аккаунта с правами «Редактор» — сайт показывает эту почту в разделе
   «Google Таблица».
4. Записать ссылку на таблицу в `GOOGLE_TABLE` в `.env`.
