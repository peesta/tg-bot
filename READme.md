# Учёт сроков годности — сайт

Сайт для учёта продукции на предприятии общественного питания: заморозка,
разморозка партий, сроки годности, списание и продажи. Раньше это был
Telegram-бот (см. ветку `main`); здесь он заменён сайтом с теми же разделами
и общей базой данных `storage/db.py`. План работ: [`ToDo.md`](ToDo.md).

## Запуск

1. Установить зависимости: `pip install -r requirements.txt`.
2. По желанию создать `.env` по образцу [`.env.example`](.env.example):
   - `HOST`, `PORT` — адрес и порт сайта (по умолчанию `127.0.0.1:8000`).
     Чтобы сайт открывался с телефонов в сети кафе, укажите `HOST=0.0.0.0`
     и откройте `http://IP-компьютера:8000`;
   - `SECRET_KEY` — ключ подписи сессий; если не задан, создаётся сам
     в `data/secret_key`;
   - `SECURE_COOKIES=1` — если сайт работает только по HTTPS;
   - `GOOGLE_TABLE` — ссылка на Google Таблицу для экспорта и импорта.
3. Запустить: `python main.py` (сервер waitress). Для разработки —
   `python main.py --debug`.

База данных — `data/database.db`, журнал сервера — `data/logs/app.log`,
резервные копии — `data/backups/`. Время на сайте — время сервера.

База, оставшаяся от Telegram-бота, подхватывается автоматически: сотрудники
бота сохраняются (с логином вида `tg123456789` и без пароля — пароль задаёт
администратор), история операций не теряется.

## Учётные записи

Регистрации нет. При первом запуске создаются две учётные записи:

| Логин      | Пароль     | Роль          |
| ---------- | ---------- | ------------- |
| `admin`    | `admin`    | администратор |
| `employee` | `employee` | сотрудник     |

Пока пароль совпадает с логином, сайт показывает предупреждение —
**смените пароли после первого входа** (раздел «Профиль»). Остальных
сотрудников добавляет администратор в разделе «Сотрудники».

Если единственный администратор забыл пароль:
`python main.py set-password admin` — задаёт новый пароль и включает доступ
(если такого логина нет, создаёт администратора).

## Что умеет сайт

Сайт выглядит по-разному для ролей. У сотрудника — бирюзовая шапка, крупные
плитки на главной и меню вкладками (удобно с телефона на кухне). У
администратора — тёмная боковая панель с разделами «Работа» и
«Администрирование», сводка с цифрами на главной.

| Раздел                          | Сотрудник | Администратор |
| ------------------------------- | :-------: | :-----------: |
| 📦 Достать из заморозки          | ✅ | ✅ |
| ❄️ Добавить заморозку            | ✅ | ✅ |
| ⚠️ Сегодня заканчивается срок    | ✅ | ✅ |
| 🗑️ Списание и продажа            | ✅ | ✅ |
| 📊 Остатки (холодильник и морозильник) | ✅ | ✅ |
| 📋 История списаний              | ✅ | ✅ |
| 👤 Профиль, смена своего пароля  | ✅ | ✅ |
| 🏷️ Товары: добавить, изменить сроки и категорию, переименовать, удалить | — | ✅ |
| 👥 Сотрудники: добавить, роль, отключить доступ, новый пароль | — | ✅ |
| 🗄️ База данных: просмотр и правка любой таблицы, поиск, CSV | — | ✅ |
| 📜 Логи: операции, действия на сайте, ошибки, журнал сервера | — | ✅ |
| 📤 Google Таблица: экспорт и импорт | — | ✅ |
| 💾 Резервные копии: создать, скачать, восстановить | — | ✅ |

Особенности:
- редактор базы работает мимо проверок сайта (например, переименование
  товара там не переносит остатки — для этого есть раздел «Товары»),
  поэтому каждая правка пишется в журнал действий, а сам журнал с сайта
  изменить нельзя; хеши паролей в редакторе не видны;
- администратор не может сменить роль и отключить доступ самому себе;
- отключённого сотрудника и сотрудника, которому сменили пароль, сразу
  выкидывает с сайта на всех устройствах;
- уведомление в начале смены: после первого за день открытия сайта
  сотрудник видит товары, у которых сегодня заканчивается срок, и
  просроченные (не показывается, если первым делом открыт «Сегодня
  заканчивается срок»).

## Безопасность

- пароли хранятся только в виде хешей (scrypt);
- после 5 неудачных попыток входа логин блокируется с этого адреса на
  5 минут, все попытки входа записываются в журнал действий;
- все формы защищены CSRF-токеном, сессия живёт 12 часов;
- для работы через интернет сайт нужно поставить за HTTPS (nginx, Caddy)
  и включить `SECURE_COOKIES=1`.

## Тесты

Из корня проекта (после `pip install -r requirements.txt`):

```
python -m unittest -v
```

Один файл: `python -m unittest tests.test_web -v`.

Тесты не обращаются к Google: Google Таблица имитируется в памяти (с ней
работает настоящий `gspread`). Сайт проверяется тестовым клиентом Flask.
У каждого теста своя временная база, рабочая `data/database.db` не
затрагивается, файл `.env` не читается.

| Файл                          | Что проверяет                                         |
| ----------------------------- | ----------------------------------------------------- |
| `tests/test_db.py`            | методы базы данных, переход с базы бота               |
| `tests/test_web.py`           | вход, роли, все разделы сотрудника и администратора, редактор базы, логи, копии |
| `tests/test_google_sheets.py` | экспорт и импорт Google Таблицы                       |
| `tests/test_config.py`        | настройки из `.env`, команда `set-password`           |

## Google Таблица

В разделе «📤 Google Таблица» у администратора есть кнопки экспорта и
импорта. Таблица одна, в ней три листа с названиями как у таблиц базы:
`products`, `freezer`, `fridge`. В первой строке листа — названия столбцов,
как в базе:

| Лист       | Столбцы                                                         |
| ---------- | --------------------------------------------------------------- |
| `products` | `name`, `fridge_storage_time`, `freezer_storage_time`, `category` |
| `freezer`  | `product_name`, `quantity`                                      |
| `fridge`   | `id`, `product_name`, `quantity`, `date_added`, `expiration_date` |

Экспорт стирает эти три листа и записывает в них текущие данные из базы.
Остальные листы таблицы не трогаются, недостающие листы создаются.

Импорт заменяет товары, морозильник и холодильник в базе данными из листов.
Сотрудники и журнал операций не меняются, импорт в журнал операций не
пишется (но попадает в журнал действий). Перед заменой сайт проверяет все
строки и при любой ошибке ничего не меняет, а показывает список ошибок с
номерами строк. Перед заменой копия базы сохраняется в `data/backups/`.

Правила для импорта:
- `fridge_storage_time`, `quantity` — целые числа больше нуля;
  `freezer_storage_time` и `category` можно не заполнять;
- товар на листе `freezer` должен быть на листе `products`;
- даты — `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ`; пустой `date_added` — сегодня;
- пустой `id` партии — сайт присвоит новый номер.

Настройка доступа:
1. В Google Cloud включить Google Sheets API и Google Drive API, создать
   сервисный аккаунт и JSON-ключ к нему.
2. Положить ключ в корень проекта под именем `credentials.json` (файл в
   `.gitignore`, в git не попадает).
3. В таблице открыть «Настройки доступа» и добавить почту сервисного
   аккаунта (`client_email` из ключа) с правами «Редактор» — сайт
   показывает эту почту на странице «Google Таблица».
4. Записать ссылку на таблицу в `GOOGLE_TABLE` в `.env`.

# Техническое задание

Исходное ТЗ было написано для Telegram-бота. На сайте те же разделы: кнопки
главного меню стали пунктами меню, «⚙ Настройки» — разделами
администратора, Telegram ID — логином и паролем.

## Назначение

Разработать Telegram-бота для учёта сроков годности продукции на предприятии общественного питания (кафе, суши-бар, пекарня и т.д.).

Бот должен помогать сотрудникам:

- учитывать продукцию, доставаемую из заморозки;
- контролировать сроки годности;
- выводить список продукции с истекающим сроком;
- оформлять списание просроченной продукции;
- оформлять продажи продуктов;
- минимизировать ручной ввод данных за счёт кнопок.

---

## Основные требования

### Требования к БД

[x] 1. Справочник продукции

Должен существовать список продукции.

Для каждого товара задаются:

- название;
- срок хранения после разморозки (целое количество дней);
- срок хранения в морозильнике (пока что это поле пустое);

Пример:

Товар| Срок в холодильнике
Филадельфия| 2 дня
Калифорния| 2 дня
Лосось| 3 дня

Администратор должен иметь возможность добавлять новые позиции и изменять сроки хранения.

2.1. Добавить заморозку

Кнопка:

❄️ Добавить заморозку

Бот предлагает выбрать товар из справочника товаров (все позиции, которые
продаются), по 5 на странице, с кнопками «Назад», «Поиск», «Далее».

Затем бот предлагает выбрать количество: 1, 2, 3 или «Ввести число».

После выбора количества товар добавляется в морозильник (если он там уже
есть, остаток увеличивается), операция записывается в журнал.

---

3. Достать из заморозки - Реализовано в базе данных

При нажатии кнопки:

"📦 Достать из заморозки"

бот предлагает выбрать товар из списка.

После выбора товара бот предлагает выбрать количество.

Количество можно:

- выбрать кнопками;
- либо ввести вручную.

После подтверждения бот:

1. создаёт новую партию;
2. автоматически рассчитывает дату и время окончания срока годности;
3. уменьшает остаток в морозильнике;
4. сохраняет данные в базе.

Если после разморозки остаток товара в морозильнике стал равен нулю, запись
этого товара удаляется из морозильника.

Пример ответа:

Добавлено:

Филадельфия — 5 шт

Дата разморозки:
17.08.2026 09:00

Годен до:
19.08.2026 09:00

---

4. Учёт партий - реализовано

Каждая разморозка должна храниться отдельно.

Пример:

Филадельфия — 5 шт — годна до 19.08

Филадельфия — 3 шт — годна до 20.08

Бот не должен объединять партии с разными сроками.

---

5. Остатки - реализовано в БД

Кнопка:

📊 Остатки

Показывает все существующие партии с положительным остатком.

Пример:

Филадельфия — 5 шт — до 19.08

Калифорния — 3 шт — до 20.08

Лосось — 4 шт — до 21.08

Просроченные партии отображать отдельно.

9. Роли пользователей - реализовано в БД

Необходимо минимум две роли.

Администратор

Может:

- добавлять товары;
- удалять товары;
- менять сроки хранения;

Сотрудник

Может:

- добавлять разморозку;
- просматривать остатки;
- выполнять списание.

# Отложенная функциональность

На текущем этапе не планируются:

- самостоятельная или автоматическая регистрация пользователей — сотрудников
  вручную добавляет администратор;
- раздел «📈 Статистика», включая расчёт количества размороженной, проданной и
  списанной продукции, процента списаний и выбор периода.

История операций и списаний продолжает сохраняться независимо от отсутствия
раздела статистики.

## Уведомление в начале смены

Расписание смен не подключено, поэтому уведомление не рассылается всем в
фиксированное время. Каждый пользователь видит его после своего первого за
день открытия сайта — не больше одного раза в день.

Уведомление не отправляется, если продуктов с истекающим сроком нет, а также
если пользователь первым делом сам открыл «⚠ Сегодня заканчивается срок».

Пример:

⚠ Сегодня заканчивается срок годности:

Филадельфия — 2 шт

Калифорния — 4 шт

Просроченные партии, которые ещё не списаны, перечисляются отдельно.
