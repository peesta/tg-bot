# Работа с базой данных

Файл `[db.py](./db.py)` содержит текущую реализацию SQLite-хранилища
для учёта поставок, морозильных остатков, партий в холодильнике и операций
с продуктами.

Документ описывает только уже реализованное поведение. Планируемые функции
из `CODE_SPECIFICATION.md`, которых пока нет в коде, здесь не рассматриваются.

## Быстрый старт

```python
from storage.db import Database


database = Database("data/example.db")

with database.cursor() as cursor:
    cursor.execute(
        """
        INSERT OR IGNORE INTO products (
            name,
            fridge_storage_time,
            freezer_storage_time,
            category
        )
        VALUES (?, ?, ?, ?)
        """,
        ("Лосось", 3, 30, "Рыба"),
    )
    cursor.execute(
        """
        INSERT OR IGNORE INTO users (
            telegram_id,
            full_name,
            role,
            is_active
        )
        VALUES (?, ?, ?, ?)
        """,
        (101, "Иван Иванов", "employee", True),
    )

database.new_delivery("Лосось", 10, user_id=101)
database.move_to_fridge("Лосось", 4, user_id=101)
```

При создании `Database` родительская директория и файл базы создаются
автоматически. Если таблицы уже существуют, их данные сохраняются.

## Глобальный экземпляр

В конце модуля объявлен готовый экземпляр:

```python
DB = Database()
```

Он использует путь `data/database.db`. Поэтому обычный импорт
`storage.db` инициализирует базу по этому пути:

```python
from storage.db import DB
```

Для тестов и изолированных сценариев лучше создавать отдельный экземпляр
`Database` с собственным путём.

## Схема базы данных



### `products`

Справочник продуктов.


| Поле                   | Назначение                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------- |
| `name`                 | Уникальное название продукта и первичный ключ                                         |
| `fridge_storage_time`  | Срок хранения в холодильнике; текущий код интерпретирует значение как количество дней |
| `freezer_storage_time` | Срок хранения в морозильнике; пока сохраняется, но не используется в расчётах         |
| `category`             | Необязательная категория; пока не используется в фильтрации                           |


Методов управления справочником пока нет. Продукты добавляются прямым
SQL-запросом через `cursor()`.

### `freezer`

Агрегированные остатки в морозильнике.


| Поле           | Назначение                         |
| -------------- | ---------------------------------- |
| `product_name` | Название продукта и первичный ключ |
| `quantity`     | Положительное количество продукта  |


Для каждого продукта хранится одна строка. Повторная поставка увеличивает
существующее количество. После перемещения всего остатка в холодильник строка
удаляется, потому что схема не допускает нулевое значение `quantity`.

### `fridge`

Отдельные партии продуктов в холодильнике.


| Поле              | Назначение                                  |
| ----------------- | ------------------------------------------- |
| `id`              | Идентификатор партии                        |
| `product_name`    | Название продукта                           |
| `quantity`        | Текущий остаток партии                      |
| `date_added`      | Дата добавления в формате `YYYY-MM-DD`      |
| `expiration_date` | Дата окончания срока в формате `YYYY-MM-DD` |


Каждый вызов `move_to_fridge()` создаёт новую партию. Партии с разными
сроками не объединяются.

### `users`

Минимальные данные пользователей.


| Поле          | Назначение                      |
| ------------- | ------------------------------- |
| `telegram_id` | Telegram ID и первичный ключ    |
| `full_name`   | Полное имя                      |
| `role`        | Роль `admin` или `employee`     |
| `is_active`   | Признак активности пользователя |


Методов управления пользователями пока нет.

### `operations`

Журнал движения продуктов.


| Поле             | Назначение                                            |
| ---------------- | ----------------------------------------------------- |
| `id`             | Идентификатор операции                                |
| `operation_type` | `delivery`, `defrost`, `sale` или `write_off`         |
| `product_name`   | Название продукта                                     |
| `batch_id`       | Связанная партия холодильника или `NULL` для поставки |
| `quantity`       | Количество продукта в операции                        |
| `reason`         | Причина списания, если она задана                     |
| `created_at`     | Дата и время операции в YYYY-MM-DD HH:MM              |
| `created_by`     | Идентификатор пользователя                            |


Для `created_at` и `created_by` создаются индексы.

Если метод вызван без `user_id`, в `created_by` записывается системный
идентификатор `0`.

## Соединения и транзакции



### `Database(path_to_db="data/database.db")`

Создаёт объект хранилища и инициализирует схему.

Аргумент:

- `path_to_db` — путь к SQLite-файлу.

Используется только файловая база данны, поскольку Database постоянно открывает и закрывает соединения.

### `get_conn()`

Возвращает новое `sqlite3.Connection` с `sqlite3.Row` в качестве
`row_factory`. Благодаря этому значения можно читать по имени поля:

```python
connection = database.get_conn()
try:
    row = connection.execute(
        "SELECT product_name, quantity FROM freezer LIMIT 1"
    ).fetchone()
    if row:
        print(row["product_name"], row["quantity"])
finally:
    connection.close()
```

Вызывающий код самостоятельно отвечает за закрытие соединения,
полученного через `get_conn()`.

### `cursor()`

Контекстный менеджер для безопасной работы с транзакцией:

```python
with database.cursor() as cursor:
    cursor.execute("SELECT * FROM products")
    products = cursor.fetchall()
```

Поведение:

- открывает новое соединение и курсор;
- выполняет `commit`, если блок завершился успешно;
- выполняет `rollback`, если возникло исключение;
- всегда закрывает соединение;
- повторно передаёт исключение вызывающему коду.



## Публичные операции



### `new_delivery(product_name, quantity, user_id=None) -> str`

Добавляет поставку в морозильник.

```python
message = database.new_delivery(
    product_name="Лосось",
    quantity=10,
    user_id=101,
)
```

В одной транзакции метод:

1. создаёт остаток продукта или увеличивает существующий;
2. записывает операцию `delivery`;
3. возвращает сообщение об успешном добавлении.

`quantity` должен быть положительным целым числом. Ноль, отрицательное
значение, `bool` или другой тип приводят к `ValueError`.

Текущая версия не проверяет наличие продукта в таблице `products`.

### `move_to_fridge(product_name, quantity, user_id=None) -> str`

Перемещает продукт из морозильника в новую партию холодильника.

```python
message = database.move_to_fridge(
    product_name="Лосось",
    quantity=4,
    user_id=101,
)
```

Метод:

1. проверяет положительность `quantity`;
2. проверяет наличие и достаточность остатка в морозильнике;
3. получает `fridge_storage_time` из `products`;
4. вычисляет дату окончания срока;
5. создаёт отдельную строку в `fridge`;
6. уменьшает остаток морозильника или удаляет его при полном перемещении;
7. записывает операцию `defrost`.

Если продукта нет в морозильнике или количества недостаточно, метод вызывает ошибку и не изменяет базу. Если продукт отсутствует в справочнике `products`, возникает `ValueError`.

Все изменения выполняются в одной транзакции.

### `get_expiring_products()`

Возвращает просроченные партии и партии, срок которых заканчивается сегодня.

```python
result = database.get_expiring_products()

if result:
    expired, expiring_today = result
```

Каждый элемент имеет вид:

```python
(batch_id, product_name, quantity)
```

Результат:

- `None`, если подходящих партий нет;
- кортеж `(expired_products, expiring_today)` в остальных случаях.

Партия считается просроченной, если `expiration_date` меньше сегодняшней даты.
Равная сегодняшней дате партия попадает в `expiring_today`.

### `clear_expired_product(...) -> str | bool`

Метод поддерживает два режима.

#### Списание всей просрочки

Вызов без данных конкретной партии списывает все партии, просроченные
до сегодняшнего дня:

```python
result = database.clear_expired_product(user_id=101)
```

Также допустим полностью безаргументный вызов:

```python
result = database.clear_expired_product()
```

В этом случае в журнале используется системный пользователь `0`.

Для каждой просроченной партии метод:

1. записывает операцию `write_off`;
2. устанавливает причину `expired`;
3. удаляет партию из `fridge`.

Партии, срок которых заканчивается сегодня, не удаляются. Если просрочки нет,
возвращается `False`. В случае успеха возвращается итоговое сообщение
с количеством партий и единиц продукта.

#### Продажа или списание одной партии

```python
result = database.clear_expired_product(
    id=12,
    quantity=2,
    operation_type="sale",
    user_id=101,
)
```

Аргументы:

- `id` — идентификатор партии;
- `quantity` — количество, которое нужно изъять;
- `operation_type` — тип операции или причина списания;
- `user_id` — исполнитель;
- `name` — устаревший совместимый аргумент, который сейчас не используется
для поиска партии.

Интерпретация `operation_type`:


| Значение            | Запись в журнале                             |
| ------------------- | -------------------------------------------- |
| `None`              | `write_off`, причина `NULL`                  |
| `"write_off"`       | `write_off`, причина `NULL`                  |
| `"sale"`            | `sale`, причина `NULL`                       |
| Любая другая строка | `write_off`, строка сохраняется как `reason` |


Если после операции часть партии остаётся, обновляется её `quantity`.
Если изымается весь остаток, партия удаляется.

Метод возвращает `False`, если партия не найдена или запрошенное количество
превышает остаток. Отсутствующие `id` или `quantity` и неположительное
количество приводят к `ValueError`.

### `fridge_batches_list() -> list[sqlite3.Row]`

Возвращает все партии холодильника, отсортированные по `expiration_date`:

```python
for batch in database.fridge_batches_list():
    print(
        batch["id"],
        batch["product_name"],
        batch["quantity"],
        batch["expiration_date"],
    )
```



### `freezer_products_list() -> list[sqlite3.Row]`

Возвращает текущие остатки морозильника:

```python
for product in database.freezer_products_list():
    print(product["product_name"], product["quantity"])
```



## Журналирование


| Метод                             | Тип операции | `batch_id`      | Причина                       |
| --------------------------------- | ------------ | --------------- | ----------------------------- |
| `new_delivery()`                  | `delivery`   | `NULL`          | `NULL`                        |
| `move_to_fridge()`                | `defrost`    | ID новой партии | `NULL`                        |
| Одиночная продажа                 | `sale`       | ID партии       | `NULL`                        |
| Одиночное списание                | `write_off`  | ID партии       | Переданная причина или `NULL` |
| Автоматическое списание просрочки | `write_off`  | ID партии       | `expired`                     |


Изменение остатков и создание соответствующей записи `operations` выполняются
в одной транзакции.

## Ограничения текущей версии

- Нет публичных методов для создания и изменения продуктов и пользователей.
- Нет метода получения журнала `operations`.
- Даты партий хранятся с точностью до дня, без времени и часового пояса.
- `fridge_storage_time` интерпретируется как количество дней.
- Некоторые методы пока возвращают пользовательский текст или `False`,
а не отдельные модели результата.
- Внешние ключи объявлены в схеме, но `PRAGMA foreign_keys = ON` при открытии
соединения пока не выполняется, поэтому SQLite их фактически не проверяет.
- Удалённые партии физически удаляются из `fridge`; их история остаётся
только в `operations`.
